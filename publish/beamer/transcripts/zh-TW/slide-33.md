# 幻燈片 33：衝突落定前的工作立場

九條編號立場，直到檢查點推翻或確認預測。幻燈片：編號清單，緊湊。口播：逐條讀；連到主張 ID A6/A7/A8 與衝突 C1–C10。

**1. 混合：智慧體搜尋；編譯器 lowering（不替換）。**
控制面 vs 資料面分裂自幻燈片 6。C6-B lean 貫穿 Horizon B（~2029–31）。

**2. Magellan ∥ MLGO — 平行押注（C1）。**
可出貨的演化 C++ 與樹內神經顧問並存，直到公開 llvm patch 或 EmitC-MLGO 客戶預設落定賽局。別過早封王。

**3. 折扣單一數字加速（C2）。**
廠商標題 vs 釘死 trace 上的中位數/p90。單核心 +15% 不是預設路徑 +2.5% p50 的證據。

**4. 收斂行動 + 強 oracle（C3）。**
自由 IR 改寫很脆弱（mlirAgent 低於 identity）。Lean：hint、ACF、pass 清單——建議性後設資料，由傳統施用器驗證。

**5. 降級通用 SCM AI（C7）。**
Forge Copilot ≠ 編譯器-oracle 審查。T9 溯源與領域 admit 機制才重要；通用程式碼補全不會落定檢查點。

**6. 覆蓋率→效能；沒有自主晶片設計（C9 / C10）。**
TritorX→KernelEvolve 階梯是 bring-up 手冊，不是 EDA 替代品。智慧體提案方言／ISA 回饋；人類擁有 tape-out。

**7. 約 6–7 個資料面層帶；不合併就外掛（A6 / S6）。**
今天 L1–L6 必備；L7* 機群成熟中。智慧體跨層帶統一契約，不是一個 mega-IR。功耗、$/token、SLO 變成目標 + oracle，不是新 IR 層帶。

**8. E2E 最適*尋求*：在 F 下聯合搜尋（A7 / S7）。**
產品適應度 F——延遲、能耗、$/token、品質、叢集——當 Pareto／約束前沿。聯合／雙層搜尋加 F-admit 與 freeze；不主張唯一全域最適。

**9. Horizon B 軟合併 M1；硬替換 M3 不主張（A8 / C6）。**
M1：e2e 控制器 + 跨層帶工具的 admit／trace；資料面留著。M2：有爭議的搜尋面合併 ~2029–31。M3：沒有經典 admit／fallback——不主張。「我只跟智慧體講話」常常是 M1 + freeze。

收尾：在 Tier A／★ 證據移動前，用這九條運作。別把各機構分歧平均掉。
