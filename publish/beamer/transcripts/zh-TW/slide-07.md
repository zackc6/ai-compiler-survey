# 幻燈片 7：四項智慧體工作 — 架構脊柱

這四項工作是調查 §5.1 的架構支柱。每個產品宣告都應對應到其中之一。它們坐在經典 lowering **之上**，而不是取代它。幻燈片頁尾正是這句；再說一次。

**(a) 線上——提議 → 量測 → 接納。**
執行時或近執行時特化：智慧體提出核心變體、pass 順序或 pragma；編譯器量測；判定預言機堆疊接納，或回退到經典路徑。幻燈片例子：**CompileIQ**（ACF 級控制產物）、**GEAK v4**（在 sglang/vLLM 上做 Amdahl 端到端與熱 A/B）、**Cake**（型別化排程 IR，NVIDIA/CMU）、**Argus**（tag/assert + SMT 接納，MI300X）。口頭節拍：這是有明確接納的熱路徑特化——不是默默預設全部。有人問非 GPU 時，再提 ACCLAIM 與 HintPilot 這對 CPU／多層表親。

**(b) 離線 — 演化啟發式 → C++ / MLGO。**
智慧體離線搜尋；輸出是簽入 **VCS**（版本控制系統）的可出貨產物：C++ 啟發式（Magellan **EVOLVE-BLOCK**），或給樹內神經顧問的特徵。**MLGO**（機器學習引導最佳化——LLVM 的學習型 pass 顧問）是樹內路徑；Magellan 是演化 C++ 路徑。兩者可以並存——這是 C1 檢查點。例子：Magellan、AlphaEvolve。

**(c) 工程 — 判定預言機閘控的 PR / 變更。**
智慧體提出編譯器補丁、方言新增或啟發式更新；人加上判定預言機審查後才合併。**Archer** 級：判定預言機閘控的拉取請求（**PR**）流程。**llvm-harness**（南方科技大學 / ETH / 港中文）加上對智慧體友善的 LLVM 工具與 **llvm-bench**（334 個中端崩潰／誤編譯缺陷）。專家審查後，真正端到端修復率仍低於 22%——智慧體起草；人與判定預言機接納。

**(d) 使能／拉起 — 覆蓋 → 效能，模擬 + 晶片。**
新硬體 SKU：先贏*覆蓋*（跨算子面正確核心），再贏*效能*。模擬 ↔ 矽迴授提出 ISA／方言調整——**TritorX**、**KernelEvolve** 是工業 A 級。**Zomboss**（密西根大學 / 德州大學奧斯汀分校）是學術類比：把機器語意一次編譯成對映面；智慧體搜意圖，不是原生 ISA。56/56 驗證通過，對照直接神經只有 26/56——**不是**第二供應商出貨的 TritorX 重播（**C9** 仍開）。軟硬體協同迴授，但沒有自主 EDA（**C10**）。

**現場診斷。**
若供應商簡報對不上 (a)–(d)，問它實際在做哪一項。「我們替換你的編譯器」通常是錯包裝的 (b)，或沒有接納的無約束 (a)——標起來。

收尾：四項工作、一條不變量——經典 lowering 留下；智慧體負責在它周圍搜尋與合成。
