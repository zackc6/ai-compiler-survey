# 幻燈片 7：四項智慧體工作 — 建築脊柱

這四項工作是調查 §5.1 中的架構支柱。每個產品宣告都應對映到其中之一。它們位於經典降低的**上方**，而不是取代它。幻燈片上的頁尾線正是說明了這一點；重複一遍。

**(a) 線上——提議 → 措施 → 承認。**
執行時或近執行時專門化：智慧體提出核心變體、傳遞順序或編譯指示集；編譯器措施； 決定機堆疊承認或退回到古典。幻燈片上的示例：**CompileIQ**（ACF 級控制工件）、**GEAK**（AMD 核心智慧體迴圈）、**ACCLAIM**（帶上智慧體指南）、**HintPilot**（編譯器驗證的編譯指示）。口頭節拍：這是明確承認的熱路徑專業化——而不是沉默的預設全部。

**(b) 離線 — 進化啟發式 → C++ / MLGO。**
離線智慧體搜尋；輸出是檢查到 **VCS**（版本控制系統）的可交付工件：C++ 啟發式 (Magellan **EVOLVE-BLOCK**) 或樹內神經顧問的功能。 **MLGO**（機器學習引導最佳化 - LLVM 的學習傳遞顧問）是樹內路徑； Magellan 是 C++ 的進化之路。兩者可能共存——C1 檢查點。示例：Magellan、AlphaEvolve。

**(c) 工程 — 判定預示機控 PR / 變更。**
智慧體提出編譯器補丁、方言新增或啟發式更新；人類加上判定機在合併前進行審查。 **Archer**-class：判定預測機控拉取請求（**PR**）工作流程 - 智慧體是一名具有嚴格 linter 和測試套件的初級工程師，而不是一個無人監督的提交者。

**(d) 啟動 — 覆蓋範圍 → 效能、SIM + 晶片。**
新硬體 SKU：首先獲勝的是*覆蓋範圍*（跨操作表面的正確核心），然後是*效能*。 Sim ↔ 矽反饋迴路提出 ISA/方言調整 — **TritorX**、**KernelEvolve** 作為 A 級證據參考。這是無需自主 EDA (**C10**) 的軟硬體良好設計反饋。

**房間診斷。**
如果供應商推介與 (a)–(d) 不相符，請詢問其實際從事哪項工作。 “我們替換你的編譯器”通常是錯誤打包的 (b) 或不受約束的 (a) 而不承認 - 標記它。

結束節奏：四項工作，一項不變——經典的降低保持； 智慧體負責圍繞它進行搜尋和綜合。
