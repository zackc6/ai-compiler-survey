# 幻燈片 31：技術預測 — 現在缺少關鍵部件

加速地平線 A 的最高槓杆投注。幻燈片上：四個編號帶，右側帶有“w/o → 結果”。口語：優先考慮這些，然後再考慮外圍編譯器內部。

**1.金錢級主機堆疊 (T2 + T6) — 不帶 → 演示。**
本地正式（Alive2 級）→ 形狀網格差異→ 統計服務判定預測機→ 分階段推出。 T2 承認機器和 T6 一起服務 A/B——而不是單獨的單元測試。阻滯劑 1 和間隙 4.2 在此匯聚。如果沒有這個階梯，智慧體就會產生快速但錯誤的核心，從而透過廉價的檢查。

**2.可重玩的工件合約 (T3) — 不包含 → CI 拒絕。**
控制檔案、核心、具有內容定址快取金鑰的啟發式以及模型/編譯器升級的黃金重播。 ACF定格是產品的形狀。如果沒有重播，每一次智慧體執行都是一次性的；構建 CI 不能倒退，服務前凍結也是不可能的。

**3.行動式智慧體編譯介面 (T1) — 無需 → 重新粘合。**
摘要、操作、承認記錄可跨 MLIR、Triton、Tile、StableHLO 移植。如今，每個供應商都連線定製的工具伺服器。如果沒有 T1，混合堆疊就會支離破碎——您為每個基板傳送一個演示，而不是一個平臺。

**4.開放梯形圖 + 多紅外資料 (T7 + T8) — 無 → 無可比擬。**
統一階梯上的正確性×速度×每次編譯的美元，加上語料庫中的負面（失敗）示例。沒有編譯成本和服務級別的 KernelBench 標題無法解決 C2 或 C9。

**調查精益頁尾。**
T1–T5 作為編譯器邊界內的產品表面交付； T6-T10 同樣是一流的——大部分都在經典降低之外。 F（產品適應性：延遲、能量、美元/代幣、質量、叢集）下的 E2E 最優尋求需要全部十個；軟合併 M1 統一了最佳化器，而不是執行基礎。

結束節奏：首先為這四個資金提供資金。其他一切都是在你還沒有的證據和合同之上的加速。
