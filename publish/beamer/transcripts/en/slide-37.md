# Slide 37: Appendix — evidence map

Appendix overview — three buckets. On-slide: Publications, Products, Repositories columns. Spoken: orient the audience; explain tiers and the ★ marker.

**Publications (~115 digests).**
One file per source — papers, blogs, talks, forge pages, meeting minutes. ★ = prediction-critical: mechanisms that directly bear on C1–C10, blockers, or T1–T10. Not every digest is equal; star entries are what you read first when a conflict is live.

**Products — commercial SKUs as prediction signals.**
Tier A shapes what the hybrid future looks like — agent loops, kernel surfaces, cloud agent products that change compile workflows. Tier B = data-plane defaults agents must plug into: Inductor, XLA/StableHLO, TensorRT-LLM, FlashInfer runtime, etc. Not a full SKU list — curated for the prediction.

**Repositories — forge artifacts tiered A/B/C.**
GitHub, Gerrit, and other forges. Tier A = agents + domain oracles change heuristics, kernels, knobs, or review (Magellan, CompileIQ, GEAK class). Tier B = data-plane hosts. Tier C = generic forge AI only — demoted for prediction (C7).

**When to reach for this slide.**
Someone asks “where’s the evidence for X?” — point to bucket and tier. Contested checkpoint → ★ digests + Tier A only. Do not cite Tier C repos as compiler-agent settlement.

Closing line: three buckets, two priority tiers (★ and Tier A). Everything else is context.
