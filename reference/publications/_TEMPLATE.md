# Full source title

| Field | Value |
|---|---|
| **Year** | Publication year |
| **Org** | Primary company, university, or laboratory affiliations |
| **Publisher** | Venue, documentation host, repository host, or preprint host |
| **Type** | paper, company, forum, talk, or code |
| **Group** | Publication-index group |
| **Link** | [Primary source](https://example.org) |
| **Evidence tier** | A, B, or C: relevance to a named design decision, not a quality score |
| **Version / reviewed** | Source version or update date; review date |

## Key contributions

Explain the mechanism in plain language. Expand necessary abbreviations at first use.

## Summary

State what was built or studied and distinguish demonstrated behavior from the authors’ vision.

## Key takeaways

For numerical results, state the baseline, measured object, hardware, workload, budget when available, and validation scope. Distinguish kernel speed, application performance, and search cost.

## Why it matters for this survey

Name the design choice this evidence informs. Explain the implication and link descriptively to related sources. Identify sources from the same system or research lineage; avoid bare claim codes and symbol-led section references.

## Limits / caveats

State what the evidence cannot establish, what remains unavailable or unverified, and which experiment would strengthen or weaken the conclusion.
